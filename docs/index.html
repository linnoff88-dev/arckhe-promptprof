O que é

Um estúdio de vídeo que cabe num repositório.

Três peças encadeadas: um motor de prompts (KairoBoost), um servidor de imagem local (inemaimg) e um renderizador de vídeo determinístico (HyperFrames). Cada vídeo é um pequeno projeto: 14 cenas, narração TTS, fundo cinematográfico com movimento de câmera e a CTA do INEMA.CLUB no fim.

Como funciona

O pipeline em 3 etapas.

01

Prompt · KairoBoost

Um system prompt de “diretor de arte” transforma uma intenção curta (ex.: “cachorro na praia”) em prompt cinematográfico estruturado — lente, luz, color grading, textura.

SYSTEM-PROMPT.mdpresets.md
02

Imagem · inemaimg

Servidor FastAPI local (DGX) gera as stills 9:16 com flux2-klein em ~9s cada. Sem API paga. Uma imagem-metáfora por cena.

localhost:8000flux2-klein
03

Vídeo · HyperFrames

Compõe HTML/CSS/GSAP → MP4 com narração TTS (pf_dora), blur + Ken Burns dirigido, legendas karaokê e CTA INEMA.CLUB.

HTML → MP4TTS Kokoro
Mão na massa

Passo a passo (comandos).

Cada vídeo vive em <projeto>/video/. O timing é fonte única: a duração real do áudio alimenta áudio E animação.

# 1) projeto + fontes
npx hyperframes init video --example blank --non-interactive
node fetch-fonts.mjs                  # Sora · Inter · JetBrains Mono → assets/fonts

# 2) narração (14 faixas TTS, voz pf_dora)
bash narration.sh                     # gera assets/audio/sN.wav + durações

# 3) imagens (14 stills 9:16 via inemaimg local)
node generate-image-inemaimg.js assets/img/s1.png "<prompt cinematográfico>" flux2-klein 9:16

# 4) compor + validar
node build-index.mjs --vertical       # gera index.html (9:16)
npx hyperframes lint                  # 0 erros
npx hyperframes inspect --samples 16  # 0 problemas de layout

# 5) render
npx hyperframes render --quality high --output renders/meu-video-9x16.mp4

Receita

Como criar um vídeo novo.

  1. Defina o assunto e o roteiro
    Gancho + N pontos + CTA. Cada cena = 1 frase curta de narração (~3–5s).
  2. Escreva a narração
    Edite narration.sh com os textos e rode — gera os WAV e mede as durações reais.
  3. Gere as imagens-metáfora
    Traduza cada ponto numa cena visual concreta (use o KairoBoost) e gere no inemaimg.
  4. Configure o build
    No build-index.mjs: array AUDIO[] (durações), LESSONS[] (títulos/subs), CAPTIONS[] e o movimento por cena.
  5. Valide e renderize
    lint 0 erros + inspect 0 problemas → render --quality high.

Dúvidas

FAQ.

Precisa de chave de API paga?
Não. Imagem (inemaimg/flux2-klein), voz (Kokoro) e render (HyperFrames) rodam local. Só os vídeos finais não vão pro git (pesados) — o resto é tudo reproduzível.
Como o áudio fica sincronizado com a animação?
Timing é fonte única: o array AUDIO[] com as durações reais (medidas via ffprobe) alimenta tanto o data-start/duration quanto os tempos dos tweens GSAP. Áudio e movimento sempre batem.
Posso usar comercialmente?
O flux2-klein é FLUX Non-Commercial. Para uso comercial troque por qwen-edit-2511 (Apache 2.0) ou ernie no inemaimg.
Dá pra fazer 16:9 (YouTube)?
Sim — o build-index.mjs roda node build-index.mjs (16:9) ou --vertical (9:16). Os overrides body.v já reenquadram tudo.
Quantas cenas por vídeo?
O padrão aqui é 14 (gancho + 12 + CTA), mas é livre: o nº de cenas = nº de itens nos arrays. 4–12 cenas de conteúdo é o range saudável pra Shorts.
